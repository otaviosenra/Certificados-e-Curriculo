## Branch Naming
Because a single code folder can be opened from several different VS Code workspaces at the same time, every branch MUST encode the VS Code workspace it originated from.

Pattern the Developer MUST use:
`<type>/<ws-code>-<ticket-or-slug>-<short-description>`
- type ∈ {feat, fix, chore, refactor, docs, test}
- ws-code = identifier of the originating VS Code workspace (see "Workspace Code Source")
- example: `feat/WSABC-PROJ-123-login-rate-limit`
- the `<type>/` prefix stays first so branch-protection / CI prefix rules keep working.

## Workspace Code Source
Each VS Code workspace declares its OWN code, so the same shared folder yields a different branch name depending on which workspace produced the change. The code must come from the workspace side, never from the folder (which is shared). Recommended mechanism:
- In each workspace's `.code-workspace` file, set a workspace-scoped terminal env var:
  `"settings": { "terminal.integrated.env.linux": { "AI_WS_CODE": "WSABC" } }`
  (add `.osx` / `.windows` keys as needed for your OS)
- The Developer reads it at branch time (`echo $AI_WS_CODE`) and injects it into the branch name.
- Fallback if unset: derive from the open `.code-workspace` file name; if still unknown, STOP and ask. Never create a branch with a missing or placeholder ws-code.
